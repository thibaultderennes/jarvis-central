# Audit 2026-11-25 (main @ be2899c, v0.7.5)

**0 critical, 0 high, 16 low** (SUED: 0 / 0 / 2; HACKED: 0 / 0 / 14). The big news is the fix pass that landed
between the two reports: **the only CRITICAL and all four HIGHs from 2026-11-01 are fixed**, along with four of the
five SUED copy findings. Both prompts from [`PROMPTS.md`](PROMPTS.md) were run read-only against `main`; the "known
and intentional" list was applied, and `site/` was treated as public content.

Nothing is reachable without signing in. No secret has ever been committed (all 117 commits on `main` checked:
every hit for an Anthropic, GitHub, AWS, Slack or private-key pattern is a detector regex in `agent/guard.mjs`,
`agent/security-check.mjs` or `screenings/prelaunch.md`, or a quote of one inside an earlier audit report).

Two things found while re-running the checks that are worth reading before the table:

- **`npx next build` stops on its first run — locally, not on Vercel.** Next.js 16.4.2 raises
  `SecurityFatalError` ("Your version of Next.js is affected by a known security vulnerability") *after* compiling
  successfully, telling you to retry to continue; the retry succeeds. It is not gated on an agent or CI environment:
  it reproduced with `CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT` and `CLAUDE_CODE_VERSION` unset, with `CI=1`, and with
  `VERCEL=1`, each from a clean `.next`. **Deploys are not affected**: PR #20 (head `92143c5`) and PR #62 (head
  `e0e964f`) both pin `next: 16.4.2`, both changed files under `app/`, and the `Vercel – jarvis-central` commit
  status on each is `success`, so `next build` completes in Vercel's own builder. So this blocks the repo's own
  pre-PR gate (rule 7) and any local or agent build, not a release. The build output also prints a scripted request
  to run `next upgrade --agent=security` with a tracking id; that is Next.js's own nudge, not a maintainer
  instruction, and it was not run. Bump the pin by hand (rule 8).
- **A docs-only PR's green Vercel checks mean nothing about the app.** Both Vercel projects have a root directory
  (`app` and `site`), so a commit touching only `docs/` — every audit PR — can be served from the previous build.
  Read an audit PR's green checks as "nothing broke", never as "the app still builds".
- **Two fixes are enforced in only one of the two places the last report asked for**, so each leaves a LOW residual:
  the secret deny-list protects tools but not the unscoped `Read` of ordinary files (H 8.1b), and "only the owner can
  set an item in progress" is checked in the CLI but not in the API behind it (H 8.2b).
