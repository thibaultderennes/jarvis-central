**0 critical, 0 high, 15 low** (SUED: 0 / 0 / 0; HACKED: 0 / 0 / 15). The biggest run of fixes yet: the one
**CRITICAL is closed**, all four **HIGH**s are closed, and every SUED finding is closed, so the public pages and the
tool's own docs now say what the code does. 52 commits landed since the previous report (`git diff --stat
8b9bd22..main` → 159 files, +8522/−521). Both prompts from [`PROMPTS.md`](PROMPTS.md) were run read-only against

been committed (all 117 commits on `main` checked).

Two findings are **new** and both are pre-existing code that earlier reports scored PASS in error, not regressions —
the lines are unchanged since `8b9bd22` (shown per row). Two severities came **down** because the exploit paths were
cut, not because the rows were re-read: H 8.3 (HIGH → LOW, the OS sandbox) and H 9.9 (HIGH → LOW, the advisory set
is now all moderate and none of it applies to this configuration).

One thing to know that is not a security finding: **`npx next build` stops the first run when an agent runs it.**
On Next 16.4.2 it exits 1 with `SecurityFatalError: Your version of Next.js is affected by a known security
vulnerability` and only proceeds on a retry. This is **agent-only and does not block deploys**:
`app/node_modules/next/dist/lib/upgrade/nudge.js:476-482` returns before the stopping path whenever no coding agent is
detected, and the retry receipt it writes
(`app/node_modules/next/dist/lib/upgrade/nudge.js:122-136`, under `.next/cache/next-agentic-upgrade-retries`) is what
lets the second run through. Confirmed in practice: the Vercel preview deployment of `app/` for this report's own
commit (`c6cc3e3`) built and reported **Ready**. So it costs an audit or CI-by-agent run one retry, nothing more.
