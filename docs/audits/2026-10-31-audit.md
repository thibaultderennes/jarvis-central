## Why no fix PRs

The routine opens a fix pull request for each CRITICAL or regression. There are none: no check moved from PASS to
FAIL, and no FAIL meets the CRITICAL rubric ("anyone on the internet can use it without signing in, or it leaks
secrets or money") with a path:line to back it. Every unauthenticated surface is the login route, the two token
routes, and the static login page and icons; everything else redirects through `app/proxy.ts:6`.

The one call worth the maintainer's attention: **H 9.9 is rated critical upstream and was not escalated here.** The
reachable-without-signing-in surface is `/_next/image`, which `app/proxy.ts:14` does let through, so the image
advisories were checked hardest; both are blocked in this tree (no `dangerouslyAllowSVG`, no `remotePatterns`, and
`app/package-lock.json:2569` already pins the `sharp` version the advisory names as the workaround). That is
configuration holding the line, not a patched dependency, so it is one config edit away from mattering. The fix is a
single line — `next@16.4.3` in `app/package.json:17`, then `npm audit fix` for the build-time `source-map-js`
advisory — and it belongs in the next change the maintainer makes, ahead of the ranked list below.
