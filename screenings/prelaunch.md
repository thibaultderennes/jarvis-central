# Website pre-launch review: check list (researched 2026-10-05)

How to read it:
- **Where**: `code` = can be checked from the source folder alone. `live` = needs the deployed URL (or a `next build && next start` local prod server for most of them). `both` = start in code, confirm live.
- **Severity**: `blocker` = do not launch. `high` = fix before launch or the same week. `med` = first week after launch. `low` = nice to have.
- Commands assume `$URL=https://example.com`, the repo root as cwd, and a Next.js App Router layout where one is named. Equivalents for other stacks are noted (`public/`, `static/`, `dist/`, `_headers`, `netlify.toml`, `vercel.json`).
- Useful tools: `npx lighthouse`, `npx unlighthouse` (whole-site), `npx linkinator`, `npx @axe-core/cli` / `npx pa11y`, `npx gitleaks` / `trufflehog`, `dig`, `curl -sI`, PageSpeed Insights API, securityheaders.com, Mozilla HTTP Observatory, opengraph.xyz, Google Rich Results Test, mail-tester.com.

Seed checks from the owner are all included (marked ★).

Size: 90 checks in 13 categories, over the 40–60 target. Severity splits them: 11 blocker + 34 high = **45 core checks** (always run), and 30 med + 15 low = extended pass (run when time allows, or report them as suggestions). Checks that don't apply (e.g. hreflang on a single-language site, pricing on a free site) are reported as n/a, not as failures.

## 1. Legal & trust

| id | category | check | why it matters | how to detect (repo / command) | where | severity | fix |
|---|---|---|---|---|---|---|---|
| privacy-policy ★ | legal | A privacy policy page exists, is linked in the footer, and names what is actually collected (analytics, forms, cookies, AI providers, processors) | Required by GDPR/UK GDPR/CCPA as soon as you collect any personal data (even an email or an IP in analytics); Chrome Web Store, App Store, Google OAuth and Stripe all demand a URL | `ls app/privacy* app/**/privacy* pages/privacy*`; `grep -rniE "privacy" app/**/footer* components/**/footer*`; compare the vendors named in it against `package.json` deps and `<Script src=` hosts; live: `curl -s -o /dev/null -w "%{http_code}" $URL/privacy` | both | blocker | Write the page from the real data flows; list processors (Vercel, analytics, email, AI); contact address; last-updated date; link from footer and every form |

## 2. Security

| id | category | check | why it matters | how to detect (repo / command) | where | severity | fix |
|---|---|---|---|---|---|---|---|
| secrets-frontend ★ | security | No secret keys in client bundles, `NEXT_PUBLIC_*`/`VITE_*`/`PUBLIC_*` vars, or committed files | Anything public-prefixed or imported into a client component ships to every visitor; leaked keys get abused within hours | `grep -rnE "NEXT_PUBLIC_[A-Z_]*(SECRET|KEY|TOKEN|PASSWORD|PRIVATE)" .`; `grep -rnE "sk_live_|sk-ant-|sk-proj-|AKIA[0-9A-Z]{16}|service_role|-----BEGIN" --exclude-dir=node_modules .`; `npx gitleaks detect --source . -v` (scans git history too); after `next build`: `grep -rE "sk_live_|sk-ant-|service_role" .next/static` | code | blocker | Move to server-only env vars; read them in Route Handlers/Server Actions; `import 'server-only'` in data modules; rotate any key that was ever exposed |
| env-gitignored | security | `.env*` (except `.env.example`) is gitignored and not in git history | Committed env files are the #1 leak source | `git check-ignore .env .env.local`; `git log --all --diff-filter=A --name-only -- '*.env*'`; `cat .gitignore` | code | blocker | Add `.env*` + `!.env.example` to `.gitignore`; purge history and rotate if found |
| https-forced ★ | security | HTTP redirects to HTTPS (301/308), certificate valid, no mixed content | Browsers flag non-HTTPS; mixed content gets blocked; SEO signal | `curl -sI http://example.com \| head -3` (expect 301/308 to https); `curl -sI $URL`; mixed content: `grep -rn "http://" app components public --include=*.{tsx,jsx,ts,js,html,css} \| grep -v "localhost\|w3.org"`; SSL: `echo \| openssl s_client -connect example.com:443 -servername example.com 2>/dev/null \| openssl x509 -noout -dates` | both | blocker | Vercel/Netlify do this automatically for attached domains; otherwise redirect at the CDN; replace `http://` asset URLs |
| hsts | security | `Strict-Transport-Security` header set (e.g. `max-age=63072000; includeSubDomains; preload`) | Stops SSL-stripping on first hop; OWASP baseline | `curl -sI $URL \| grep -i strict-transport`; code: `grep -n "Strict-Transport" next.config.* vercel.json middleware.* proxy.* netlify.toml public/_headers` | both | high | Add via `headers()` in `next.config.js` (Vercel sets a default HSTS on its domains, but verify on the custom domain) |
| security-headers | security | `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY` or CSP `frame-ancestors`, `Permissions-Policy` restricting camera/mic/geolocation | Blocks MIME sniffing, clickjacking, referrer leaks; Vercel's Next.js conformance rule flags missing headers | `curl -sI $URL \| grep -iE "x-content-type|referrer-policy|x-frame|permissions-policy|content-security"`; scan: securityheaders.com or `npx observatory-cli example.com` (Mozilla HTTP Observatory); code: `async headers()` block in `next.config.*` | both | high | Add a `headers()` entry for `source: '/(.*)'` with the set above |
| csp | security | A Content-Security-Policy (at least report-only at launch) | Main defence against XSS and injected third-party scripts; recommended by both Vercel and Next.js checklists | `curl -sI $URL \| grep -i content-security-policy`; `grep -rn "Content-Security-Policy" next.config.* middleware.* proxy.*` | both | med | Start with `Content-Security-Policy-Report-Only`, then enforce; Next.js nonce pattern in middleware/proxy for inline scripts |
| x-powered-by | security | `X-Powered-By: Next.js` and server version banners removed | Free fingerprinting for attackers | `curl -sI $URL \| grep -i x-powered-by`; `grep -n poweredByHeader next.config.*` | both | low | `poweredByHeader: false` in `next.config.js` |
| server-auth-checks | security | Every Server Action / API route that mutates data checks auth and ownership on the server; no reliance on middleware alone | Server Actions are public POST endpoints; Next.js docs explicitly say not to rely on Proxy/layout checks alone | `grep -rln "\"use server\"\|'use server'" app src`; `ls app/api/**/route.ts`; read each for `auth()`/`getSession`/`getUser` before writes | code | blocker (if any auth) | Put authZ in a `server-only` data access layer; validate input with zod |
| deps-vulns | security | No known critical vulnerabilities in dependencies; lockfile committed; framework on a patched version | Next.js had critical CVEs in 2025 (middleware auth bypass CVE-2025-29927, React Server Components RCE in Dec 2025) | `npm audit --omit=dev --audit-level=high` (or `pnpm audit`); `git ls-files \| grep -E "lock"`; `npx next --version` vs latest patch | code | high | `npm update next react react-dom`; fix or override vulnerable deps |
| rate-limit-api | security | Public endpoints (forms, auth, AI calls, email send) are rate limited | Prevents abuse, spam floods and runaway AI/email bills | `grep -rnE "ratelimit|rate-limit|@upstash/ratelimit|limiter" app src lib`; Vercel WAF rate-limit rules in dashboard | code | high (if paid APIs behind it) | `@upstash/ratelimit` keyed on IP/user, or Vercel WAF rate-limit rule; set spend caps on AI/email providers |
| security-txt | security | `/.well-known/security.txt` with contact and expiry (RFC 9116) | Gives researchers a way to report issues instead of posting them | `ls public/.well-known/security.txt`; `curl -s $URL/.well-known/security.txt` | both | low | Add the file with `Contact:` and `Expires:` |

## 3. SEO & indexability

| id | category | check | why it matters | how to detect (repo / command) | where | severity | fix |
|---|---|---|---|---|---|---|---|
| meta-title-desc ★ | seo | Every indexable page has a unique `<title>` (~50–60 chars) and meta description (~120–160 chars); no default "Create Next App" | Titles are the search result headline and tab label; duplicates hurt CTR | `grep -rn "Create Next App\|Generated by create next app\|Vite + React\|React App" app src index.html`; `grep -rLn "export const metadata\|generateMetadata" app/**/page.tsx` (pages without metadata); live: `curl -s $URL \| grep -oE "<title>[^<]*</title>\|<meta name=\"description\"[^>]*>"` | both | high | `metadata` / `generateMetadata` per page plus `title.template` in the root layout |
| robots-txt ★ | seo | `robots.txt` exists, allows crawling of production, references the sitemap, and does not `Disallow: /` | A leftover `Disallow: /` from staging silently de-indexes the site | `ls app/robots.ts public/robots.txt static/robots.txt`; `curl -s $URL/robots.txt` | both | blocker (if Disallow: /) | `app/robots.ts` returning `rules: { userAgent: '*', allow: '/' }, sitemap: '<abs url>/sitemap.xml'`; decide on AI crawlers (GPTBot, ClaudeBot, Google-Extended) deliberately |
| sitemap ★ | seo | `sitemap.xml` exists, lists only canonical 200 URLs with absolute production URLs, submitted in Search Console / Bing Webmaster | Faster discovery; wrong host (localhost, *.vercel.app) is a common bug | `ls app/sitemap.ts public/sitemap*.xml`; `curl -s $URL/sitemap.xml \| grep -oE "<loc>[^<]+" \| head`; `grep -c "localhost\|vercel.app" ` on that output | both | high | `app/sitemap.ts` built from routes/CMS; base URL from one `SITE_URL` env |
| noindex-prod | seo | Production pages do NOT carry `noindex`, staging/preview DO | `robots: { index: false }` copied to prod is a classic launch-killer; Vercel adds `X-Robots-Tag: noindex` on previews but NOT on a custom staging domain | `grep -rnE "noindex|index: false|robots:\s*\{" app src`; `curl -sI $URL \| grep -i x-robots-tag` (should be empty on prod); `curl -s $URL \| grep -i "noindex"`; `curl -sI https://staging.example.com \| grep -i x-robots` (should show noindex) | both | blocker | Gate robots metadata on `process.env.VERCEL_ENV === 'production'`; add `X-Robots-Tag: noindex` header for non-prod hosts; protect staging with Deployment Protection |
| canonical | seo | Each page has a self-referencing absolute `rel=canonical` on the primary domain; `metadataBase` set | Consolidates www/apex, trailing-slash, query-param and *.vercel.app duplicates | `grep -rn "metadataBase\|alternates" app/layout.* app/**/page.*`; `curl -s $URL \| grep -oE "<link rel=\"canonical\"[^>]*>"` | both | high | `metadataBase: new URL(SITE_URL)` in root layout + `alternates: { canonical: '/path' }` |
| structured-data | seo | JSON-LD for the site type (Organization + WebSite; Product/SoftwareApplication, FAQPage, Article as relevant) validates | Enables rich results and helps AI/answer engines understand the entity | `grep -rn "application/ld+json" app components`; live: Google Rich Results Test or `https://validator.schema.org` | both | med | Add a `<script type="application/ld+json">` in layout/page with `JSON.stringify(schema)` |
| hreflang | seo | If multilingual: `hreflang` alternates for each locale + `x-default`, reciprocal, and `<html lang>` correct | Wrong-language results and duplicate-content issues across locales | `grep -rn "languages:\|hreflang" app`; `grep -rn "<html lang" app/layout.*`; `curl -s $URL \| grep -i hreflang` | both | med (n/a single-language) | `alternates.languages` in metadata; set `lang` per locale |
| html-lang | seo/a11y | `<html lang="…">` set correctly | Screen readers pick pronunciation; search engines language detection | `grep -n "<html" app/layout.* src/index.html` | code | med | `<html lang="en">` (or locale) |
| heading-structure | seo/a11y | Exactly one `<h1>` per page, logical heading order | Accessibility navigation and topical relevance | live: `curl -s $URL \| grep -oc "<h1"`; axe rule `page-has-heading-one`, `heading-order` | live | med | Fix heading levels; don't pick headings for font size |
| search-console | seo | Domain verified in Google Search Console (and Bing Webmaster), sitemap submitted | Only way to see indexing errors, manual actions, CWV field data | `grep -rn "google-site-verification\|verification:" app`; `dig TXT example.com +short \| grep google-site-verification` | both | med | Verify via DNS TXT; submit sitemap on launch day |
| clean-urls-redirects | seo | Old/renamed URLs 301 to new ones; no redirect chains; consistent trailing slash | Preserves link equity and avoids 404s from old shares | `grep -n "redirects()" -A30 next.config.*`; `cat vercel.json`; `curl -sIL $URL/old-path \| grep -iE "^HTTP\|location"` | both | med | Add `redirects()` entries (permanent: true) |

## 5. Performance

|---|---|---|---|---|---|---|---|

| fonts | perf | Fonts self-hosted via `next/font` (or preloaded with `font-display: swap`); no render-blocking Google Fonts `<link>` | Removes a third-party request, avoids FOIT and layout shift | `grep -rn "fonts.googleapis.com\|fonts.gstatic.com\|@import url(" app src styles`; `grep -rn "next/font" app` | code | med | `next/font/google` or `next/font/local`; subset; limit weights |

| caching | perf | Static assets served with long immutable cache; HTML/data caching intentional; no accidental full-dynamic routes | Repeat visits and CDN hit ratio; cost on Vercel functions | `curl -sI $URL/_next/static/... \| grep -i cache-control` (expect `max-age=31536000, immutable`); `curl -sI $URL \| grep -iE "cache-control|x-vercel-cache|age"`; `next build` route table (○ static vs ƒ dynamic); `grep -rn "cookies()\|headers()\|force-dynamic\|no-store" app` | both | med | Keep marketing pages static/ISR; avoid `cookies()` in root layout; set `Cache-Control` for public assets |
| compression-http2 | perf | Text responses compressed (br/gzip), HTTP/2 or 3 | Smaller transfers | `curl -sI -H "Accept-Encoding: br,gzip" $URL \| grep -i content-encoding`; `curl -sI --http2 $URL \| head -1` | live | low | Default on Vercel/Netlify/Cloudflare; enable on custom servers |
| function-region | perf | Serverless/edge function region matches the database/API region | Cross-continent DB round-trips add hundreds of ms TTFB | `grep -n "regions\|preferredRegion" vercel.json app/**/route.* app/**/page.*`; compare with DB host region | code | med | Set `regions` in `vercel.json` or `preferredRegion` per route |

## Suggested run order for the review (fast to slow)

1. **Code-only sweep (no URL needed):** secrets/env grep + gitleaks → placeholder/lorem/`href="#"` grep → metadata/robots/sitemap/icon/opengraph files present → `noindex` grep → forms validation + spam grep → build flags + `tsc` + `npm audit` → `next build` route table and First Load JS.
2. **Local prod server:** `next build && next start`, then linkinator, axe/pa11y, Lighthouse against `http://localhost:3000`.
3. **Live URL:** `curl -sI` header block (HTTPS, HSTS, security headers, X-Robots-Tag, cache), www/apex redirects, 404 status, robots/sitemap content, OG preview, PageSpeed Insights field data, DNS (`dig` MX/SPF/DMARC/DKIM/CAA), real form + email + signup end-to-end.
4. **Ask the owner:** uptime monitor, backups, spend caps, account access, which counts/testimonials are real.

One-shot header check:
```sh
curl -sI https://example.com | grep -iE "^HTTP|strict-transport|content-security|x-content-type|referrer-policy|x-frame|permissions-policy|x-robots-tag|x-powered-by|cache-control"
```
